# P0.2 — Calculator Divergence Measurement

**Task:** BygSmart 3.0 Native, Phase P0, deliverable 0.2. Sizes ~a quarter of the programme (E5 / P4).
**Method:** every calculator page opened and classified. Measured, not estimated.
**Date:** 2026-08-04

## Locations (verified, absolute paths in the 2.1 reference repo)
- **Central catalog:** `modules/tools/catalog.ts` — single file, ~90 `compute*` formula functions + `STANDARDS_CATALOG`, `getCalculator`, `catalogHelpToContent`. This is the "catalog.ts" the docs reference.
- **Calculator pages:** `modules/tools/pages/<Category>/*.tsx`.
- **Note:** the target-architecture path `legacy/modules/tools/pages` does **not** exist yet — pages currently live at `modules/tools/pages`.
- **Exact page count: 89** (excludes non-calculators `CalculationToolsPage.tsx`, `ToolsConfiguratorPage.tsx`, `MeasurementTool.tsx`, and the smoke test).

## Classification rule
- **A – DELEGATES:** every substantive result comes from a catalog `compute*` function; only trivial inline arithmetic (unit conversion, area/qty scaling, single factor, rounding).
- **B – PARTIAL:** delegates at least one result AND computes at least one genuine engineering result via its own multi-term inline formula.
- **C – OWN MATHS:** uses **no** catalog `compute*` function for any result (no catalog import, or imports only metadata helpers while computing everything inline).

## Summary counts
| Class | Count | Meaning |
|---|---:|---|
| **A** pure delegation | **55** | Harvest the catalog function; page becomes a schema entry |
| **B** partial | **11** | UValue, WindowArea, FuseSizing, DewPoint, HeatLoss, ExhaustFan, Rafter, SlabLoad, RoofSnowLoad, BoilerSizing, DrainSlope — inline maths must be reconciled into the engine |
| **C** own maths | **23** | 19 no-catalog-import (incl. deliberate StairCalculator) + 4 metadata-only importers (RoomArea, FloorArea, CircuitLoad, PaintEstimatorPro) |
| **Total** | **89** | |

## Escalation verdict
**Divergence = B + C = 11 + 23 = 34.** Threshold: "exceeds 40 of ~90".
**→ THRESHOLD NOT CROSSED (34 ≤ 40).** No escalation.

**Sensitivity:** C=23 is robust (verifiably call no catalog `compute*`). B=11 is the judgment-sensitive band: a stricter B rule → ~29; a very liberal rule (any non-trivial inline arithmetic) → up to ~40. Even at the generous end it does not clearly exceed 40, so the verdict holds, though the 6-below-threshold margin is moderate, not comfortable.

## Consequence for P4 / E5
- ~55 calculators are near-mechanical harvests (catalog fn → pure function + schema entry + golden fixture).
- ~34 need real remediation work; of these the 23 own-maths pages and 11 partials are where formula correctness review (and "fix where 2.1 was wrong") concentrates.
- Confirms the phase-readiness review's descope is sound: ship the ~20 highest-value calculators in P4, deliver the long tail (the harvest-heavy A set) in v1.1 at ~1 dev-day each.
